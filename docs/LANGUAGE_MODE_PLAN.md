# 目標語言改為可設定（預設簡體）：評估與優先順序

> 狀態：**評估報告，尚未實作**。等你確認第 6 節的順序後才開始改程式。
> 依據：反編譯 1.7.4998 的 `Verse.LoadedLanguage`、`Verse.DefInjectionPackage`（ilspycmd）。未在遊戲內實測的項目標為【未實測】。

## 1. 對照組件確認的載入規則（修正階段 1 報告）

| 項目 | 組件中的實際行為 | 對簡體模式的意義 |
|---|---|---|
| 語言資料夾順序 | 依 `RunningMods`（模組載入順序），每個模組再依 `foldersToLoadDescendingOrder`；資料夾名稱比對完整名稱 `ChineseSimplified (简体中文)` 或括號前的 `ChineseSimplified` | 翻譯包排在被翻譯模組**之後**就會後載入 |
| Keyed 跨檔／跨模組同鍵 | `keyedReplacements.SetOrAdd`：**後載入者直接覆蓋，不記錄錯誤** | 翻譯包可以覆蓋既有簡中的 Keyed 條目，技術上安全 |
| Keyed 同一檔內重複鍵 | 記錄錯誤，遊戲最後彙總成一行黃色警告「Translation data … has N errors」 | 我們的輸出檔不會有同檔重複 |
| DefInjected 單一欄位同鍵 | 載入時記錄 "Duplicate def-injected translation key"，但仍以 `SetOrAdd` **後者覆蓋**；且注入階段開頭會 `loadErrors.Clear()`，這則訊息**不會被計入警告**【未實測】 | 覆蓋可行，但每次重新產生翻譯報告時會看到這些訊息 |
| DefInjected 整串清單（`<li>`）同鍵 | 用 `injections.Add`，重複時丟例外；例外在 `AddDataFromFile` 被接住，**該檔案中此元素之後的所有條目都不會載入** | **絕對不能覆蓋整串清單**；否則會連帶丟失同檔其他翻譯 |
| 不同寫法指向同一欄位（索引 vs handle） | 注入時記錄 "Both X and Y refer to the same field"，計入警告，取用哪一筆取決於字典順序 | 維持現有做法：偵測到「同一個 Def 被其他翻譯以可能不同寫法觸及」就不輸出 |

階段 1 報告寫「DefInjected 重複鍵會報錯」只對了一半：會記錄，但會被清掉、且仍是後者覆蓋。已在 `STAGE1_REPORT.md` 加註更正。

## 2. 簡體模式的行為（你的第 2 點）

### 2.1 既有簡體視為已翻譯，只補缺漏
- 「已翻譯」判斷改為看 `TargetLanguage` 對應的資料夾（簡體模式：`ChineseSimplified*`），範圍是**啟用中**的模組（含翻譯補丁）。現有程式本來就是依設定值比對，改動小。
- 只補：模組有簡中但缺的鍵、缺的 DefInjected 欄位、完全沒有簡中的模組。
- 你的 400 個啟用模組：之前抽查的 40 個「有簡中、無繁中」模組，在簡體模式下多數會變成「幾乎不用翻」。實際缺漏數要等改完後重新統計。

### 2.2 過期簡體條目
簡中條目存在、但與目前英文對不上（佔位符不一致、EN 註解不同）時：

| 做法 | 可行性 | 風險 |
|---|---|---|
| A. 只在報告中列出（**建議預設**） | 完全安全 | 遊戲仍顯示舊譯文 |
| B. 翻譯包覆蓋 Keyed 過期條目 | 可行（`SetOrAdd`，無錯誤） | 過期判斷錯誤時會蓋掉正確的人工翻譯；需翻譯包排在原翻譯之後 |
| C. 覆蓋 DefInjected 單一欄位 | 可行【未實測】 | 同上；另外重新產生翻譯報告時會出現 duplicate 訊息 |
| D. 覆蓋 DefInjected 整串清單 | **不可行** | 會讓翻譯包同檔後續條目全部失效 |

建議：預設 A；加一個**使用者才能開**的 `override_stale`（可按模組設定），只允許 B、C，且只對「佔位符不一致」這種強證據生效（EN 註解不同只列報告）。覆蓋條目放在獨立檔案，並在 manifest 註記，可一鍵撤回。D 永遠不做。

### 2.3 用詞與現有簡中一致
簡體模式下 get_batch 的 memory／terms 改為：
1. **同英文的既有簡中**（新）：記憶池中所有已安裝模組（含未啟用的漢化補丁）的簡中，配上同模組同鍵的英文，建立「英文 → 簡中」索引。同一句英文在別的模組怎麼翻，就提示 Agent 照用。
2. **官方簡中術語**：改從官方 `ChineseSimplified` 語言包取 Def 名稱（現在取繁中）。
3. **本模組自己的簡中**：缺漏條目所在模組若已有部分簡中，附上同檔相鄰條目的譯文當風格參考。
4. **未啟用的漢化補丁中有這個條目**：直接當成候選（同語言，不需轉換），可走自動採用流程（例如你裝了但沒啟用的 RWZH 補丁）。

順序：使用者術語表 > 官方簡中 > 本模組既有簡中 > 其他模組同英文簡中 > Agent 自譯。

### 2.4 驗證規則
- 簡體模式偵測**繁體殘留**：需要 OpenCC 的 `TSCharacters`（繁→簡單字表，Apache-2.0）建立「繁體專用字」集合，作法與現在的簡體字偵測對稱。
- 其他規則（佔位符、標記、XML、長度、未翻譯）兩種模式共用。

## 4. 選配雙輸出：「Agent 翻一次，另一種語言以 OpenCC 衍生」（你的第 4 點）

### 方向選擇
| 方向 | 字形轉換 | 用詞轉換 | 評估 |
|---|---|---|---|
| Agent 翻簡體 → 衍生繁體（s2twp） | 一對多（后→後／后、发→發／髮），需歧義偵測，我們已有 | 大陸詞→台灣詞靠 TWPhrases，涵蓋不全（例：添加→新增） | 你主力是簡體，品質放在主語言；繁體為次要 |
| Agent 翻繁體 → 衍生簡體（tw2sp） | 多對一，幾乎不會錯 | 台灣詞→大陸詞同樣不全 | 字形較安全，但主語言品質受轉換影響 |

建議：**Agent 翻簡體，繁體衍生**。

### 取捨
| 優點 | 缺點 |
|---|---|
| Agent 額度只花一次 | 衍生繁體會繼承 Agent 的翻譯錯誤，且再加上轉換錯誤 |
| 兩種語言的譯名一致 | 一對多字約占 18%（前面抽查的比例），這些要嘛另外請 Agent 校對（多花額度），要嘛接受預設候選 |
| 已有的轉換、歧義偵測、分級可直接重用 | 繁體的「已翻譯」判斷要另外做（模組可能有繁中沒簡中，或相反），兩邊的缺漏集合不同 |
| 一個翻譯包可同時放兩個語言資料夾，不必兩個包 | 翻譯包變大；繁體驗證失敗的條目要能單獨略過 |

### 建議做法（選配，預設關閉）
- 同一個翻譯包輸出 `ChineseSimplified` 與 `ChineseTraditional` 兩個資料夾。
- 繁體條目來源：Agent 的簡體譯文經 s2twp + 術語表；**沒有歧義、驗證通過才輸出**，其餘列入報告或交給 Agent 校對（可設定）。
- 已有人工繁中的條目不輸出（與現在相同）。
- 衍生的繁體條目在 manifest 標記 `origin: derived_s2t`。

## 5. 安全性影響
- `TargetLanguage` 只能是 `ChineseSimplified` 或 `ChineseTraditional`（白名單），不接受任意資料夾名稱。
- 新增的「覆蓋過期條目」只能由使用者在 config.json 開啟，MCP 工具不能開。
- 新增的 OpenCC 字典（TSCharacters）一樣內嵌並記錄雜湊。

## 6. 建議實作順序（等你確認）

1. 工具回給 Agent 的訊息改英文、既有程式碼註解與 README 改英文（CLAUDE.md 新規則）。
2. `TargetLanguage` 設定值（預設 ChineseSimplified）：輸出資料夾、「已翻譯」判斷、About 名稱、官方術語來源切換。
3. 繁體殘留偵測（內嵌 TSCharacters）。
4. 簡體模式記憶：英文 → 簡中索引、本模組既有簡中、未啟用補丁候選；get_batch／query_memory 依語言切換。術語表 en 依語言分開。
5. 過期簡中報告（`rwat stale-report`），選配覆蓋列為之後再做。
6. 重新統計你目前 400 個模組在簡體模式下的缺漏量。
7. 雙輸出：放到最後，或併入階段 3 之後。

繁體模式的現有功能保留，`TargetLanguage = ChineseTraditional` 時行為與現在相同。
